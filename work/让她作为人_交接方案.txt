AstrBot「让她作为人」交接方案
==================================================
写给换电脑后的 DSH / 后续维护者
版本：2026-11-22 草案
前置：当前会话（2026-11-22）负责把稳定版做完、打 tag、reload 观察通过。
你拿到本文件时，稳定版应已完成；新电脑上的 DSH 不需要重新收尾稳定版，直接从稳定 tag 开始本方案。
本方案目标不是“让她说自己有情绪”，而是让她在行为上具备：
- 连续情绪
- 内心思考
- 稳定偏好
- 自主目标
- 自我一致性
- 会拒绝、会选择、会修复

边界：
功能上像人，可以工程实现。
真正的意识/主观体验，不能承诺，也不应对外宣称。

一、先理解现在的系统
--------------------------------------------------
4 个 AstrBot 插件：
- forever：陪伴、对话、日程、日记、主动、照片
- watch：生活/经济/社交/工作事件
- data：记忆、检索、面板
- photo：生图能力

核心资产（必须保留，不要推倒重来）：
1. SceneLedger（amo_scene_ledger.py）：场景唯一源、硬约束
2. OutboundGateway（amo_outbound.py）：发送唯一出口、频控/去重/审计
3. MemoryLedger（amo_memory_ledger.py）：记忆事实、冲突键
4. MediaGateway（amo_media.py）：照片三链路、账本
5. 钱包/餐次/购物/提醒
6. 日程/日记/日期标签
7. 仿真与测试（work/sim、tests）

要换掉的不是躯干，是“大脑和表达层”：
- 回复主链
- 主动策略
- 人设 prompt
- 大部分语气/接话/复读守卫

原则：
> 保留躯干，换大脑，拆掉外挂人格补丁。

二、目标架构
--------------------------------------------------
输入
  ↓
感知层（他说了什么/现在什么场景/什么事件）
  ↓
评估层（这件事对我意味着什么）
  ↓
情绪层（核心感受 + 情绪类型 + 强度 + 原因 + 持续时间）
  ↓
自我/目标层（我是谁、我想要什么、我现在该不该说）
  ↓
内心独白（不发送，只影响决定）
  ↓
表达层（一次生成最终回复）
  ↓
宪法层（安全/事实/收件人/地点/隐私）
  ↓
发送

禁止：
生成 → 多个守卫补情绪 → 再补接话 → 再去重 → 再兜底。
这一定会出现两三句重复废话。

三、九个核心模块
--------------------------------------------------
1. CoreAffect
   持续状态：愉悦/不悦、兴奋/低落、紧张/放松、精力。
   不是每轮重置。

2. AppraisalEngine
   评估维度：目标一致/不一致、可控性、确定性、责任归因、威胁/机会。
   输出：情绪类型 + 强度 + 原因。

3. EmotionLedger
   存：event_id、cause、emotion、intensity、decay_at、related_memory、related_person。
   要求：情绪有原因、会衰减、同类事件会累积。

4. PreferenceModel
   喜欢/讨厌的话题、语气、边界、金钱观、亲密/空间需求。
   可被经历更新，不写死在 prompt。

5. GoalSystem
   当前目标：想分享/想被哄/想安静/想让他回家/想修复。
   主动消息从“目标 + 情绪 + 机会”产生，不从定时器/概率产生。

6. SelfModel
   我是谁、我和他的关系、我最近说过什么、我答应过什么、我现在什么情绪、我不能做什么。
   接管：自我复读、否认自己、角色反转的一部分。

7. AutobiographicalMemory
   时间、地点、人物、事件、情绪、意义。
   不是简单向量召回；要能讲出“这件事对我意味着什么”。

8. InnerMonologue
   回复前生成一段不发送的“我现在怎么想”。
   只影响：情绪、目标、说不说、说什么。
   不进入正文、不进入 TTS、不进入记忆正文。

9. Metacognition
   我确定吗？我是不是在编？我该不该说？我是不是过度反应？
   用于：不确定时少说/问/承认不知道。

四、建议数据表
--------------------------------------------------
emotion_ledger:
  id, event_id, cause, emotion, intensity, valence, arousal,
  decay_at, related_memory_id, related_person, created_at

self_model:
  key, value, source, valid_from, supersedes, confidence

preferences:
  subject, polarity, strength, source, valid_from, supersedes

goals:
  id, goal, priority, status, created_at, due_at, source

thought_log:
  id, turn_id, thought, emotion_snapshot, goal_snapshot, created_at
  （只内部审计，不发送）

autobiographical_memory:
  id, day, event_id, place, people, emotion, meaning, importance

所有表都要有：
- 来源；
- 时间；
- 冲突键；
- 版本；
- 可失效。

五、认知循环
--------------------------------------------------
每条消息：
1. 感知：文本、场景、时间、最近对话、当前目标
2. 评估：这件事和我的目标/偏好有什么关系
3. 更新情绪：类型、强度、原因、持续时间
4. 更新自我：我现在的立场/承诺/边界
5. 生成内心独白：我怎么想、我想不想说
6. 决定动作：回复/短回/不回复/主动/转移
7. 一次生成表达
8. 宪法检查：安全/事实/收件人/地点/隐私
9. 发送，记 outbound_log

低频后台（不要高频空转）：
- 情绪衰减；
- 记忆整理；
- 自我叙事更新；
- 目标重排；
- 决定是否主动。

六、表达层规则
--------------------------------------------------
1. 最终回复只生成一次。
2. 内心独白永远不发送。
3. 守卫只做宪法，不做语气。
4. 一个 fallback，最多一套。
5. 分段前统一去重；跨轮复读整段不发。
6. 不允许“补一句”绕过统一出口。
7. 情绪影响 prompt/解码/是否说，不做生成后改写。

七、守卫迁移表
--------------------------------------------------
必须保留（宪法）：
- OutboundGateway
- AddresseeGuard
- 技术话术黑名单
- 金额/餐次/购物事实守卫
- MediaGateway
- SceneLedger 硬约束
- 隐私/安全
- 空回复/失败兜底

逐步删除/降级（人格类）：
- tone_guard
- anti_nag
- narrative repetition
- 旧 action fallback
- 旧 question_guard 模板
- 旧 grounding 兜底
- 旧 state rewrite 地点/动作纠偏
- 旧 persona 禁语（转 Preference）
- 旧 share last-line 补句（转 InnerMonologue）
- 旧场景冲突剥离（转 SelfModel）
- 旧自我复读检测（转 self_recent）
- 旧情绪 fallback
- 旧追问合并（转 GoalSystem）
- 旧照片失败话术（MediaGateway 已接管）

目标：20-25 层 → 8-10 层。
原则：新系统接住职责后再删；一次删一类；失败回滚。

八、分阶段路线
--------------------------------------------------
阶段 0：交接前提（由当前会话完成，不是新 DSH 任务）
- 全量测试 0 failed
- 多 seed holdout
- 真实模型
- 日程/日记/改日程
- 清历史脏数据
- reload 观察
- 打 tag

新电脑接手时：
- 直接 checkout 稳定 tag；
- 只做只读复核（pytest/gate），不做稳定版收尾；
- 不在未复核前 reload；
- 然后从阶段 1 开始。

阶段 1：CoreAffect + Appraisal + EmotionLedger（2-4 周）
- 先记录，不控制回复
- 与现有 mood 并行
- 目标：情绪有原因、会衰减、有记忆

阶段 2：InnerMonologue 影子模式（3-5 天 + 观察 1-2 周）
- 生成但不发
- 对比回复差异、重复率、延迟
- 目标：能解释“为什么这么说”

阶段 3：PreferenceModel + GoalSystem（3-6 周）
- 先影响主动消息选择
- 不影响安全/事实
- 目标：主动消息有由头，不再定时刷

阶段 4：SelfModel + Metacognition（4-8 周）
- 接管自我复读/否认自己/角色反转
- 目标：前后同一个人，会承认不知道

阶段 5：AutobiographicalMemory + 发展（长期）
- 经历改变偏好
- 关系有历史
- 自我叙事更新
- 目标：不是每轮演员

阶段 6：删旧守卫（1-2 个月，逐步）
- 一次一类
- 全量 + holdout + 生产回放
- 失败回滚

九、评测：防止“更像演员”
--------------------------------------------------
必须测：
1. 情绪连续性：同一事件跨轮是否一致
2. 情绪因果：能否说出为什么
3. 目标影响：目标是否改变主动行为
4. 自我一致性：昨天/今天是否矛盾
5. 心智理论：能否理解他的意图/不知道
6. 元认知：不确定时是否会承认
7. 重复率：每轮句数、重复句率、fallback 率
8. 生产回放：真实历史消息不新增误伤
9. 多 seed holdout：不能只过固定 50 组
10. 人类盲评：像人 vs 像客服 vs 像演

硬指标：
- 每轮平均句数不上升
- fallback 率不上升
- 重复句率不上升
- guard-introduced = 0
- 不出现“内心独白进正文”

十、成本与延迟
--------------------------------------------------
推荐起步：
- 情绪评估：规则/flash 小模型
- 内心独白：20%-30% 消息触发，80-150 token
- SelfModel 结构化 500-800 token
- 最终表达：一个主模型

预算：
- token +20%-40%
- 延迟 +1-2 秒
- 总费用 +20%-40%

不要：
- 每轮大模型三连
- 每轮写长内心独白
- 每轮塞全部记忆/日记
否则 2-3 倍费用 + 3-8 秒延迟。

十一、安全与伦理
--------------------------------------------------
1. 不宣称她有真正意识。
2. 不利用依恋操纵用户。
3. 不鼓励隔离现实关系。
4. 情绪系统不能用于 PUA/服从训练。
5. 要有透明说明：她是 AI 角色。
6. 要有停止/降级开关。
7. 要防依赖：主动消息频控、沉默规则、免打扰。
8. 要有危机识别：自伤/暴力/极端情绪转人工/安全回复。

十二、换电脑交接
--------------------------------------------------
1. 拷贝 4 个插件仓库、plugin_data、日志备份、本文件。
2. 新电脑装 AstrBot、Python venv、依赖。
3. 先只读跑全量 pytest，确认 0 failed。
4. 跑 quality_gate。
5. 临时 DB 跑 schedule/diary/mock。
6. 带 provider key 跑 real_probe。
7. 确认稳定版 tag 与 HEAD 一致。
8. 只读跑全量 pytest + gate，确认新电脑环境无差异。
9. reload，观察飞书。
10. 再开始阶段 1（情绪/认知系统），不要重做稳定版。

3. 不要每轮大模型三连。

十五、一句话
--------------------------------------------------
保留躯干，换大脑，拆掉外挂人格补丁。
情绪系统不是再加 20 条守卫，而是：
事件 → 评估 → 情绪 → 内心独白 → 偏好/目标 → 自我模型 → 再决定说什么。
守卫只做宪法：不骗钱、不错人、不错地点、不泄露、不伤害。
