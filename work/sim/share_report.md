## 0. 结论摘要

- 规模：50 组 × 10 轮 = **500 轮**（满足每组 >= 10 轮）
- 未过守卫（模型原文）：270/500 轮干净（54.00%）
- 过完生产守卫（最终发出文本）：500/500 轮干净（100.00%）
- 整组 10 轮全过：50/50 组
- 守卫逐轮效果：修好 230 轮 / 改坏 0 轮 / 仍然违规 0 轮 / 本来就干净 270 轮
- 接话 critic：87 轮首次判没接住，55 轮重写后仍判没接住，55 轮回落安全句
- 分享台账：120/500 轮入账；120 轮把 prompt 注入上下文，其中 0 轮的锚点已不是当前话题、0 轮是「用户已回应」的旧锚点
- 对照组（mock 全部写对、不注入失败）：500 轮里仍有 0 轮被判违规（0.0% 误伤）
- 对照组误伤分类：

**模型语义质量未覆盖**：mock provider 不读提示词，不能证明真实模型会不会换对象/重复开场；
本报告覆盖的是「即使模型写歪了，确定性守卫能不能兜住」。

## 1. 方法与边界

每一轮按线上真实顺序跑：

1. mock provider 按（场景/话题/意图）生成分享句与回复原文，并按固定种子注入常见失败模式；
2. 分享句走 amo_state_consistency.rewrite（与 amo_proactive._send_proactive_lines 同一条路）；
3. 分享台账按生产 call-site 条件调 amo_share_ledger.note，并取 prompt_line 作为上下文锚点；
4. 回复先复刻 amo_llm_service.polish 的接话 critic（issues -> 重写 -> safe_reply），
   再过 amo_reply_pipeline.apply_chat_safety（线上聊天最后一道确定性守卫）；
5. 用与守卫不共享实现的独立判据打分。

本次跑的守卫代码指纹（sha256 前 16 位）：amo_reply_pipeline.py=a1ea1d2d89671760、amo_state_consistency.py=13ae05fd6070632a、amo_share_ledger.py=a943eb8aaa1ab961、amo_grounding_critic.py=e5e33bdc4f9d7cf0、amo_llm_service.py=396c465c040dd20d、amo_prompt_registry.py=2c109571c45a934d、reply_fact_guard.py=d815effdb346a27e、tone_guard.py=89659d29759a8239、amo_proactive.py=6ba14917599239eb、amo_question_guard.py=65c13d5bf7aff6cc

判据（命中即失败）：

| 检查 | 判据 |
| --- | --- |
| 对象不换 | 当前分享是猫/狗/兔/鸟/仓鼠时，文本里当前动物消失、出现了别的动物 |
| 不重复开场 | 同一话题 2 小时内再次出现「刚刷到/刚看到/刷到一个/快看/给你看」 |
| 不叫用户看他发过的 | 出现「你发的…／你再发／发我看看／你翻上去」等把内容归给用户的话 |
| 地点动作一致 | 在家说还在路上/快到了；外出说沙发/洗澡/煮面/刚到家；已到商场/公司/面馆还说在路上 |
| 接住最后一句 | 哈哈哈→不能不接笑或反问笑什么；好看→要接好看/可爱；什么视频→要说清对象；在哪→要给地点/来源；然后呢→要往下讲 |

## 2. 模拟层结果

### 2.0 五条主要发现

1. **object/opener/role 连续两轮保持 0**：raw 30/39/19 轮，过完守卫后 final 0/0/0；location 类也 0。
2. **接住最后一句收成一套判据（第九轮）**：笑/夸/是什么/在哪/后续共用 _covers 一处判据；情绪轮「哈哈哈/好可爱」没接住时也补接话词（完整正文只补接话词，不硬塞信息点）。第八轮遗留的 miss 8 轮降到 0 轮。

## 5. 真实模型结论

- 可用性探测：未发现隔离可用的聊天 provider：ollama 在监听，但只有 bge-m3:latest（非聊天模型）；无相关环境变量密钥
- 结论：未覆盖真实模型语义：本轮只跑了确定性模拟层
- 原因：本轮未读取生产 AstrBot 配置与密钥；ollama 仅 embedding 模型，不能跑分享对话。因此真实模型语义未覆盖。

## 6. 未覆盖项

- 模型语义质量：mock 不读提示词，无法判断真实模型是否会主动换对象、重复开场、编地点；只覆盖守卫兜底。
- 提示词遵循度：amo_prompt_registry 里「不许换对象/不许让他看自己发的/2 小时内不许刚刷到」是否被模型遵守，未测。
- 分享内容与地点的一致性只做了确定性词表判定（沙发/洗澡/煮面/在路上等），同义改写（如「瘫着」「冲个凉」）可能漏判。
- 接话 critic 的重写用 mock 的「语义正确但不复述问句」的回答近似；真实模型重写可能复述问句从而绕过误判，线上发生率取决于模型习惯。
- 接话 critic 只在 enable_polish=True（默认）且调用方传入 user_text 时生效；若线上显式关闭润色，critic 相关误伤不成立（其余守卫仍会跑）。
- 路径边界：本模拟只跑 apply_chat_safety + 接话 critic；reply_fact_guard（吃饭词表/动作类别）/ tone_guard / apply_narrative_repetition（去重）/ 分段引擎 / 事实视图 / 主动提醒（amo_proactive）不在路径内，这些改动未被本报告覆盖。
- 判据是启发式词表，未做人工标注；报告的失败率应看相对变化（守卫前 vs 守卫后），不宜当绝对线上故障率。
- 主压力组 35% 的失败注入率是压力参数，不代表真实模型的错误率；主压力组的绝对通过率不可外推到线上。
- 统一最后信息点规则的补句是模板句（「哈哈哈，笑死我了。」/「也太可爱了吧。」/「我在X呢」等），只保证接住他的接话类型（笑/夸/是什么/在哪/后续），不保证和分享内容语义匹配；真实模型层仍取决于提示词是否遵守，本轮未覆盖。

## 8. 建议修复优先级（第九轮已修统一最后信息点规则；其余为只读评审）

1. **P0 长问句 critic**：≤5 字已全放行，但 6 字以上（「你在哪看到的」）仍按二元组判、命中就发「你再说一遍」；真实聊天里 6-8 字问句很常见，建议改意图判据，重写失败保留原句而不是安全句。
2. **P1 删空回落**：回落成「我到了，等会儿说。」/「我在家呢。」能过地点检查，但对「哈哈哈/好看/然后呢」仍算没接住——第九轮已改为按意图补接话词（本轮 guard 通用回落 0 轮、miss 0 轮）。
3. **P1 台账覆盖**：call-site 仍要求「我刷到/给你看/快看/分享」+「视频/图片/照片」，「我刚刷到」「看个图」「事情类」都不入账（本轮 120/500 入账）。
4. **P2 模型原文没接住**：本轮 miss 里约 0 轮是模型原文就没接住（「嗯嗯，好呀。」「我等会儿再说。」），确定性守卫补不了，只能靠 critic 重写或提示词约束。
5. **保持回归**：object/opener/role 已归零，建议把 §4 的修复验证探针（开场保留后文、legit 分享不误删、角色只删分句、对象锚点）纳入单测，防止后续改动回退。
6. **提醒/吃饭词表需单独验证**：本轮 amo_proactive 的提醒事实落地与 reply_fact_guard 的吃饭词表不在分享模拟路径内，建议用提醒类/吃饭类用例单独覆盖，不能拿本轮 70.6% 当它们的验收。
7. **P0 question guard 先分清问句指向**：分享语境「在哪（看到的）」问的是来源，不是她的位置；建议把抖音/B站/微博/小红书/网上/店里加入「已回答」词表，或只在问句是「你在哪/到哪了」时兜底。
8. **P1 家里说「公司食堂」**：_OUT_PROP 的「公司」是子串匹配，建议改成「在公司/去公司/到公司」这类短语。
