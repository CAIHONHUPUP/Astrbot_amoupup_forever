### 2.4 根因

1. **日期标签没有唯一来源**：\`weekday\` 由 \`jit_plan\` 参数判断、展示文案却硬编码；节气/星期在日记头由“生成时刻”的 \`day_meta\` 拼；倒计时/相对日由 LLM 自行换算。三套口径只要有一处用“现在”而不是“目标日”，就串日。
2. **写入口早于决策**：病假决策被放在 08:00-10:00（且异步），而 06:30-08:00 的地铁/早餐/迟到罚款/JIT 出门块已先写库；之后只有“健康恢复巡检”会清病假块，**不会回滚当天已写的通勤/餐费/日记行**。
3. **无“目标日对象”**：日程、账本、日记、聊天 prompt 各自用闭包里的 \`now()\`，没有把 \`target_day + hh:mm\` 作为结构体一路传递。

### 2.5 建议统一规则（详见第 9 节）

- 所有文案里的绝对/相对日期只能由 \`target_day: date\` 生成；禁止在文案模板里出现硬编码星期/节气；JIT 文案必须 \`weekday=now.weekday()\` 动态拼“周一/周二…”。
- 病假/出门等“日级状态”必须在**当天第一条副作用（早餐扣费/通勤块/迟到罚款）之前**完成决策；未决策前只允许写“待定”占位，不允许写死“出门/公司”。
- 补写/日记头必须以 \`target_day\` 的 \`day_meta()\` 与天气日数据为准，禁止用“现在”的 day_meta。

## 3. “昨天补写”审计

### 3.1 机制（代码事实）

- 配置 \`diary_time='08:00'\`，注释明确 B 方案“第二天写昨天”：\`amo_schedule.py:2365-2410\` \`_diary_time_rules(target_day)\`，当 \`target_day < now.date()\` 时提示词写“这是已经过完的 %s，素材里的[今日]都指 %s…现在是 %s %02d:%02d 在补写…”。
- 补写调度：\`amo_schedule.py:1189-1215\` 每 tick 最多补 2 条（\`diary_backfill_minute\` 限速），\`now.hour==0\` 时 \`_backfill_rollover\` 补昨天最后一段；\`amo_schedule.py:1375-1430\` 会重写最近 7 天里 \`diary_stale\` 的“大日记”，最多 7 天。

### 4.6 建议统一规则

1. **所有定时任务单飞**：\`asyncio.Lock\`/DB 原子 claim（\`UPDATE ... WHERE checked<>...\`）+ “开始即写 checked、失败再回滚”的 CAS 语义；guard 必须在发起网络请求**之前**原子写入。
2. **提醒键 = (kind, target_day, target_start, event_id/内容 hash)**，不含开始时间的键禁止用于“已提醒”判定。
3. **迟到窗口**：槽位时间 +N 分钟内允许补发（建议早间 ≤15m、晚间 ≤15m），超过则记录 \`missed\` 并在当天摘要里降级为“今天没来得及提醒”，不静默。
4. **失败可见**：天气/日程取数失败写 \`alert_status=missed\` 并进面板，不发用户消息但必须可审计。
5. **过期状态清理**：\`weather_alert_open/sent\` 按日清理；\`*_prompt\`/\`mood_line\` 必须有 TTL 且 TTL 到期删除，不能只靠“until 比较”。

### 7.4 根因

1. **账户与流水没有强约束**：唯一写入口存在，但历史修复/清理脚本绕过它写库；退款行（+1651.32）没有原扣款行可对，导致“流水合计≠余额”。
2. **“今日支出”定义错误**：\`bill_engine.summary\` 只按符号过滤，存款/投资/房租都算支出。
3. **缓存 TTL 跨天**：\`expense_summary\` 48h，写入时机是“某次消费后/某次 finance_tick”，不是“每天 0 点重算”。
4. **播报口径与真源不一致**：明细流水 26 条 vs 99 行；余额取数有“扣款前/扣款后”混用（4072）。
5. **跨插件**：钱包在 forever（\`wallet_ledger/wallet_account\`），账单/购物流在 watch，两边各自读、各自写 kv，无事务/对账任务。

### 7.5 建议统一规则

1. **单一真源**：\`wallet_account.balance_cents\` 为唯一余额；任何写库必须走 \`wallet.debit/credit\`；禁止脚本直插流水，必须提供 \`wallet.reconcile()\`。
2. **对账不变量**：\`sum(ledger where account=X) == account.balance(X)\`，每次写后校验，不等则告警并冻结播报；withdrawable 独立记账，不得镜像 cash。
3. **“今日支出”口径**：只统计 \`category in (餐饮、交通、社交、购物、其他/日常消费)\` 且排除 \`存款/投资/转账/退款/房租水电\`；退款按原笔冲销。
4. **余额取数时点**：播报统一用“扣款后余额”，且同一条消息里不混用“扣前/扣后”。
5. **缓存即失效**：\`expense_summary\` 改为“按日 key（\`expense_summary:<day>\`）+ 当日结束失效”，不要 48h 滑动 TTL；任何消费后重算当日值。

## 9. 统一规则（建议落到代码的“硬约束”）

> 以下规则按“能写成断言/守卫”的方式描述，不依赖 LLM 自觉。

### R1 时间与日期：单一 target_day
- 所有文案的“今天/昨天/明天/周X/几号/节气”必须由 \`target_day: date\` 生成；禁止模板硬编码星期/节气。
- JIT 文案：\`weekday\` 来自 \`now.weekday()\`，星期字符串集中一个函数（禁止“周一早上”这类字面量）。
- prompt 中“现在是 YYYY-MM-DD HH:MM”只用于相对时间换算；**日记/补写**必须额外给“target_day + 当前是补写时刻”。

### R2 跨天隔离
- 补写素材窗口 = \`[target_day 00:00, target_day 24:00]\`（跨零点最后一段单独标记）；跨日素材禁止进入细节。
- 迟到补写 >24h 只允许摘要；>72h 标记 skip。
- 日记头/天气/节气/节日用 \`day_meta(target_day)\` + \`weather_day[target_day]\`。

### R3 提醒单飞与幂等
- 提醒键：\`(kind, target_day, target_start, event_id or content_hash)\`；发送前 CAS 占位，失败回滚。
- 提醒提前量：日程 10-60 分钟（现有），但**文案不得说不出提前量**；播报时间误差 ≤ 5 分钟，超出记 missed。
- 定时任务（天气/日记/质检）必须有“单实例 + 开始即占位”的锁；热重载不得遗留旧 tick。

### R4 餐次实例
- \`meal:<day>:<slot>\` 是唯一餐次 ID；日程块、账本、日记、聊天都引用它。
- 一个饭点窗口只允许一个 primary meal；加餐/宵夜为 \`kind=snack\`，有日配额与金额上限。
- 扣费入口统一 \`pay_food\` 并先查 \`meal_spent\`；不再允许 JIT/hunger/micro/social 直接造餐费 idem。

### R5 金额与余额
- 金额只能来自 \`price_book\`（缺失→固定兜底+标记），禁止 LLM 报价。
- 余额/流水：\`sum(ledger)==account\` 为硬不变量；withdrawable 独立记账。
- “今日支出”口径固定（排除存款/投资/转账/退款/房租水电），按日 key 缓存、0 点失效。
- 播报统一“扣款后余额”；同一消息不混用扣前/扣后。

### R6 健康/病假日
- 日状态先于副作用；病假现金不扣，只记下月工资；迟到/通勤/早餐入口守卫。
- 健康恢复后：清病假块 + 回滚/补偿病假期间误扣 + 重写当日 JIT/日记行（事务 + 审计）。
- 病假日历：病假当天所有“去公司/通勤/食堂”写入路径统一拒绝（含 JIT/聊天/日记/钱包）。

### R7 生理期
- \`period_start\` 单一来源（kv 优先、配置只做首次写入），面板/命令/状态一致。
- 新增 \`period.pain\` 并接入日程守卫与语气；黄体期/经期/痛经日分别定义活动白名单。

### R8 旅行/出差
- 旅行/出差状态机独占日程；结束/取消作废未发生块与提醒；行程变更要播报。
- “他出差”与“她旅行”分开建模，不共用 \`away\` 语义。

### R9 可审计性
- 每个“日事实”写入（餐次/健康/提醒/余额）都带 \`day + idem + source + actor\`；面板可查“这一天到底吃了几顿、扣了几笔、为什么”。
- 一致性巡检（建议每日 00:05 + 每次写后）作为 CI/定时硬门槛：日期标签、餐次去重、余额对账、提醒幂等、健康状态冲突，任一失败禁止发“日报/日记/报账”。
