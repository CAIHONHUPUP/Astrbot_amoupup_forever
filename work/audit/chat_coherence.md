**统一根因（一句话）**：这层回复是“**单轮状态播报 + 事后正则改写**”，没有跨轮的“对话状态对象”。生成只看状态快照与最近 6–8 条纯文本，没有结构化的“他这一句在问什么 / 她上一句分享了什么 / 哪个话题还欠一句回答”；生成之后又被 30+ 道互不知情的确定性守卫按关键词改写，**语义校验（critic）在最上游、破坏语义的改写在最下游**，改写后不再复检；兜底句又分散在多套私有词池里。于是：没有话题锚点→接不上/换话题；没有答案契约→说东答西；没有统一兜底与出口幂等→重复与通用短句。

### 1.3 关键口径

- “重复”= 归一化（去空白/标点）后整句相同，或 `difflib` 相似度 ≥0.85；近义= ≥0.55。
- “未接住分享”= 她分享后 10 分钟内他给出反应（笑/夸/问什么/问在哪/要后续），她的下一条没有延续同一信息点（否认/换对象/换话题/只说状态）。
- “通用兜底”= 归一化后等于 `_GENERIC_FALLBACKS`、`SHORT_FALLBACKS`、`_GENERIC_REPLIES`、`_ACTION_FALLBACK` 或 `_align_*` 固定句之一。

### 3.1.2 频率与分布

- 主动链路：121 条 / 6.2 天 = 19.5 条/天；**4 个“≥3 条/分钟”的爆发**（其中 07:30 一次 7 条）。
- 15 分钟内近义对（sim≥0.6）10 对、≥0.55 为 11 对；24h 内 15 对；完全相同的 bot 文本 5 组（“在外面呢…”×3、“？怎么不理我了？”×2、“醒醒”×2、“我在这儿呢…”×2、自拍 ×4）。
- 历史摘要（11-08–11-18）：`喂喂，人呢？`×5、`我在这儿呢…`×3、`醒醒`×2、`怎么不理我`×2；`你还记得`×13（其中 id=932 一块内约 10 次是同一问句）。
- 用户侧重复是“因”：11-19 看脚趾/再试 20 条请求、11-19 17:30–21:00 比基尼/拍照 12 条请求、11-20 “我爱你”类 4 条——她的回复没有一次把状态真正推进（图永远“出不来”、承诺永远“最后一次”），于是对话在同一意图上打转。

### 3.1.4 机制小结

重复不是“模型偶尔啰嗦”，而是**四层都没有强约束**：生成提示词鼓励“抱怨被晾着”；跨轮去重只认 5 条/0.9 相似；发送出口去重因接口漂移失效；主动消息多入口并发且没有持久幂等键。任何一层是有效的都能挡住 07:30 的 7 条，实际四层全漏。

| `amo_grounding_critic.py:42-47` | 短反应/≤5 字放行；`_bigrams(user) & _bigrams(body)` 有交集就算接住 | 只要回复里出现“视频/笑/好看”这类话题词就算接住 → **否认内容也过**（“什么视频…没别的视频”与问题共享“视频”二字） |
| `amo_understanding.py:47-51,70-78` | 意图/对象卡：`_target` 正则弱，常回“他说的这件事”；`understanding_mode` 默认 `rules`，只有 `auto` 且置信度≥0.5 才调模型 | 默认永不走模型；置信度 0.6/0.4 是拍的 |
| `amo_reply_pipeline.py:1159-1182` `_prefer_answered_candidate` | 兜底句覆盖候选时，若候选答到问题就还原 | 白名单 `_GENERIC_FALLBACKS`（1048）不含 `SHORT_FALLBACKS` 的“嗯，我在呢/在听你说呢/我这儿一直在” → 恰好漏掉真实模型层最常见的 3 类替换 |

### 3.2.4 机制小结

说东答西不是“模型没听懂”单一原因，而是**语义检查的位置错了**：唯一会判断“有没有回答最后一句/有没有接住”的 `grounding_critic` 在 `polish` 里（生成期），而 `_align_arrival`、`_align_swim_where`、`state_consistency.rewrite`、`question_guard.answer` 都在它之后按关键词整句替换；替换后没有任何一层再问一句“这还是不是对他那句话的回答”。critic 本身又用字符 bigram 交集判定，容易被“话题词回声”绕过。

## 3.3 他顺着她的分享说，她接不上/转移话题

### 3.3.1 生产时间线样例

| 时间 | 她分享的 | 他的接话 | 她的下一句 | 判定 |
| --- | --- | --- | --- | --- |
| 11-19 20:26 | “老公，我笑到肚子疼 刚刷到一个视频太离谱了” | “视频啥内容啊” | “什么视频，刚才不是你说要看比基尼、要看脚趾吗…没别的视频。” | **否认+换题**（最严重） |
| 11-20 11:24 | “我跟你说，柳如烟刚讲了个冷笑话 我笑到在工位上憋不住” | “啥笑话，老婆” / “哈哈哈” | 先答“是方圆讲的…”，再“这有啥好笑的，你们男人笑点真低” | 前半接住、后半**否掉他的反应** |

### 3.3.2 频率

- **A 级生产抽样**：她分享后 10 分钟内他给出反应共 4 次（奶茶 1、视频 2、冷笑话 1），**3 次没接住（75%）**；其中视频分享 2 次全部失败（11-19、11-21）。
- **C 级 share_report（mock）**：无守卫时 `miss_last_line` 156/500 = **31.2%**；`opener_repeat` 39（7.8%）、`object_swap` 30（6.0%）、`asks_user_to_look` 19（3.8%）；经 1–8 轮补丁后 final `miss_last_line` 4/500 = 0.8%。**但这是 mock 层守卫验证，caveat 明确说“真实模型是否遵守提示词未测”**；且最新一轮 `prompt_injected_turns=120/500`，说明台账只覆盖了约 1/4 的轮次。
- **B 级真实模型**：`real_llm_layer.json` 的 note 说明它只跑人设+snapshot+日程，**不含生产完整提示词与分享台账**，所以真实模型下的分享接话率**没有有效证据**——这本身是验收缺口。

### 3.3.3 代码入口（快照）

| 位置 | 作用 | 问题 |
| --- | --- | --- |
| `amo_share_ledger.py:17` / `84-98` / `101-113` | 只存**最近一条**分享，TTL 2h，`pending=True` | 多话题不可用；并发分享后到先覆盖；主动消息与聊天共用同一槽 |
| `amo_share_ledger.py:145-162` `prompt_line` | 分享后把“你刚分享过 X；先接住他这句，再接着聊同一件事”注入系统提示词 | **只有提示词，没有硬校验**；模型不遵守就失败；`X` 当前仍取 `text[:60]`（快照 line 151，新加的 `info` 未用于 prompt_line），长分享会丢最后信息点 |
| `amo_reply_pipeline.py:1238-1242` | `apply_chat_safety` 里**每轮无条件** `mark_reacted` | 他只要回一句（哪怕“哈哈哈”），pending 立刻清零；后续 1–2 轮续聊没有台账可用（新增 `recent_info` 才补上“TTL 内不看 pending”的读路径） |
| `amo_runtime_context.py:1101-1110` | 把 `prompt_line` 拼进动态上下文 | 只在提示词层；且该动态块与 40+ 个其他块并列，真实模型注意力被稀释（无法验证） |

| `amo_proactive.py:1533-1538` / `amo_runtime_reply.py:179-188` | 主动/聊天分享入账条件：文本含“刷到/给你看/快看/分享”且含“视频/图片/照片” | 事情类分享（“食堂番茄炒蛋是甜的，笑死我了”）不入账，模拟报告已点名（`caveat`/probes 的 `breed`、`media_only` 项） |

### 3.3.4 机制小结

分享连续性是**纯提示词 + 单槽台账**：模型没接住时没有任何出口校验；而台账在“他回应”那一刻就被清 pending，恰好把最需要续聊的下一轮清掉。后来补的 `state_consistency` catch 是关键词 5 类 + 单条信息点，能治 mock 样例，但会过触发（任何“什么”+2h 内分享）并整条替换短答，属于“用一个补丁盖另一个补丁”。

### 3.4.2 频率

- **B 级真实模型**：短回复（<8 字）24/272 = **8.8%**；整条通用兜底 7/272 = **2.6%**（其中“还是老样子。”5 次，来自状态去重删空后的回落）。
- **A 级生产**：主动链路罐头追问 12/121 = **9.9%**；DB raw 里固定句“在外面呢…”3/184 = 1.6%，action-only 1 条。
- **C 级 mock**：300 问句探针 24 未答（8.0%），样例“你说呢？/不知道呀。/哈哈哈，你猜。”；但 mock 候选本身质量差，不能外推。

### 3.4.3 代码入口（快照）——兜底池是分裂的

| 池 | 位置 | 内容/触发 |
| --- | --- | --- |
| `_GENERIC_FALLBACKS` | `amo_reply_pipeline.py:1048-1053` | 还是老样子/等下再说/再说吧/嗯/嗯嗯/哦/好/我还在外面呢，晚点就回去 |

| `short_reply.guard` | `short_reply.py:97-123` | 客服词替换成“嗯。/好呀~”；他敷衍时“你就回我一个嗯？哼…” |
| `grounding_critic.safe_reply` | `amo_grounding_critic.py:23-32` | 你刚问的这个，我一下没答好，你再说一遍？/我在听，你接着说。 |

- 候选恢复只认第一个池：`_prefer_answered_candidate`（`amo_reply_pipeline.py:1159-1182`）→ 真实模型层被换成 `SHORT_FALLBACKS`/`_GENERIC_REPLIES` 时**不会还原**（G13/G23/G43 三例）。
- `apply_narrative_repetition` 在删空后直接 `fixed = "还是老样子。"`（`amo_reply_pipeline.py:1367`），该句进入 `_GENERIC_FALLBACKS` 可被还原，但 `_answered_intent` 又用窄词表判原候选（when 类要求“到家/路上/马上/快了/晚点/时间”），像“不回啦，我就在家歇着呢”不含这些词 → 仍不还原。
- 行动-only 兜底存在（`amo_message.py:240-250`），但 11-20 的动作-only 仍发出：说明至少有一条发送路径没经过这道兜底（具体入口需按发送栈排查）。

### 3.4.4 机制小结

“空/短/通用”不是模型爱敷衍，而是**兜底输出没有单一注册表，也没有“兜底必须回答当前问题”的契约**：各守卫删完句子后各自挑自己的短句池；候选恢复只认其中一套；问句兜底用事实模板整条替换；追问路径把“醒醒/喂喂”当禁词写进提示词而不是出口校验，旧模板仍能从模型里生成。

## 4. 统一根因：为什么四类会同时出现

### 4.1 回复链（快照，简化）

```
生成期：on_message → amo_llm._compose_reply
  → _reply_system / _reply_base_parts（40+ 提示词块：人格、状态、fact_lock、length、catch_answer、understanding、short_reply…）
  → LLM 文本
  → _reply_postprocess：polish（内含 grounding_critic 语义检查）→ short_reply.guard → 地点/消费/日期守卫
装饰期：on_decorating_result
  → _deco_soft_guards：offwork / fact_guard / apply_narrative_repetition（去重、可回落“还是老样子”）/ tone
  → _deco_rewrite_reply：防御话术/AI 自曝/后台泄漏/补图
  → _deco_polish_native
  → _deco_text_cleanup：brushoff / 饭问 / 催办 / 短句接题 / 鞋 / _align_arrival / 泳装固定句 / 交通 / 地点黑名单 / 日期 / 裁长
  → apply_chat_safety：身份/人名/消费/反催问/陪伴/婚姻/语音/state_consistency（状态改写+分享补句）/role/question_guard（整条替换）
  → 分段引擎 → 发送

主动期：_maybe_proactive → _proactive_one（slot 锁、生成、主题去重）→ _send_proactive_lines（burst、fact_guard、proactive_dedup、切句）→ _send_to_umo（send 守卫 + outbound 去重 + 分段去重 + 发送）
追问期：_check_proactive_pending → _followup_text_live（现写 20 字）→ _send_to_umo（绕过主题去重/slot/burst）
```

### 4.2 六条机制与四类问题的映射

| # | 机制 | 导致 | 关键证据 |
| --- | --- | --- | --- |
| R1 | 没有跨轮对话状态：生成只有状态快照+最近 6–8 条纯文本；分享信息、上一轮问题、待办回答都不在结构化上下文里 | ③ 接不上分享；② 换题 | `amo_runtime_context` 动态块 + `amo_share_ledger` 单槽；`amo_llm._reply_base_parts` 40+ 块无“上一轮话题”块 |
| R2 | 语义检查位置早、破坏性改写晚、改写后不复检 | ② 说东答西 | 装饰链顺序（3.2.3）；`real_llm_layer` 72/272 改写、其中 5 例把正确候选改坏 |
| R3 | 兜底池分裂 + 候选恢复白名单不同步 | ④ 通用短句；② 答不到 | `_GENERIC_FALLBACKS` vs `SHORT_FALLBACKS` vs `_GENERIC_REPLIES`；G13/G23/G43 |
| R4 | 主动消息多入口、无持久幂等：slot 锁是内存/单函数；追问路径绕过去重；切句在发送层二次发生 | ① 七连发/重复 | 07:30 日志；`amo_llm.py:908` spawn；`_check_proactive_pending:875` 直发 |
| R5 | 问句/意图识别是窄词表：question_guard 5 类、understanding 默认 rules、critic bigram | ② 问句漏答/被顶回 | `amo_question_guard:27-51`；`amo_understanding:70-78`；`amo_grounding_critic:42-47` |
| R6 | 分享连续性只有提示词：单槽 2h、pending 一回应即清、没有“接住”硬校验；新加的 catch 是关键词补丁 | ③ 接不上 | `amo_share_ledger:17/132/145`；`amo_state_consistency:357-408` |

### 4.3 为什么“逐样例补丁”不收敛（数据）

- 分享问题已经打过 **8 轮**补丁（`share_report.fix_comparison.stages`：47.2% → 43.2% → 61.4% → 63.2% → 64.4% → 68.6% → 99.2%），mock 层看似收敛；但同一时期真实模型层仍有 **9/272 失败、72/272 被改写**，生产 11-21/11-22 仍出现新变体（“晾这儿”、价格 649→985、刚到家 vs 还在路上）。
- 新补丁未接线：`amo_part_dedupe.dedupe` 专为 21:15 两句连发而写，但没有任何调用点（只剩注释）；`proactive_guard` 的 `near_duplicate` 只在 `gen_proactive` 用，追问路径不用。
- 新补丁互相打架：`_attach_last_line` 会把 ≤12 字的正确短答整条换成分享补句（③ 的修复制造 ② 的风险）；`_prefer_answered_candidate` 的白名单不包含新池；`_align_arrival` 与 `state_consistency`、“我还在路上呢”在 3 个地方各写一份。
- 守卫数量增长本身是症状：`amo_reply_pipeline.default_stages()` 登记 40+ 阶段，装饰链 20+ 次改写，每次线上问题都新增一条正则，缺一个“改写→复检”的统一收口。

## 5. 结构性修复方向（不逐样例，按优先级）

> 只读审计，以下只给方向与验收口径，不含代码补丁。

### P0（先止血，1–2 小时可验证）

1. **统一末道语义闸**：把 `grounding_critic`（或等价“是否回答最后一句/是否接住分享/是否通用兜底”）从 `polish` 里提出来，放到 `apply_chat_safety` 之后、发送之前；任何守卫改写的输出必须再过一次，失败则回炉（最多 1 次）或回退“原始候选 + 原问题答案”。验收：真实模型 100 轮里“answer 被改坏”为 0。
2. **兜底句单一注册表**：`reply/fallbacks` 一份定义，带 `intent` 槽（when/where/doing/eaten/who/content/followup/laugh/pretty）；`_GENERIC_FALLBACKS`、`SHORT_FALLBACKS`、`_GENERIC_REPLIES`、`_ACTION_FALLBACK`、`question_guard` 模板全部引用它；`_prefer_answered_candidate` 改为“最终文本 ∈ 任意 fallback 且原候选回答了问题 → 还原”。验收：真实模型层“候选正确但被替换”案例 = 0。
3. **出口去重补单测**：`amo_outbound_guard.allow(plugin, umo, text, now)` 的 source 走 contextvar；补 3 个测试（同来源 90s 近似、跨来源不串、chat 不拦）；主动消息发送后必须在 db 留幂等键（umo+kind+intent+window），重启不丢。验收：并发 10 条同意图只发 1 条。
4. **主动消息单入口/单发**：`_check_proactive_pending` 的追问也走 `_send_proactive_lines` 的 burst+主题去重；`_send_to_umo` 不再二次切句（或切句前再跑一次整条去重）；生成 1-3 句的上限放在“最终消息”而不是“part”。验收：同一分钟同会话 >1 条 = 0。

### P1（结构性，1–2 天）

5. **一个对话状态对象**（持久化 kv/json）：`{topic_id, topic_kind, last_share_info, last_user_question, pending_answer_intent, last_bot_claim(place/action/outfit), awaiting_user}`；生成前作为**一段结构化块**注入（替换现在的 40+ 条散规则里的重复段），守卫只读写它，禁止再从历史纯文本里猜。
6. **分享台账多槽 + 状态机**：最多 3 条话题槽；状态 `awaiting → reacted → followup(1-2轮) → closed`；`mark_reacted` 只从 awaiting→reacted，不直接删；`prompt_line` 按当前 user 反应类型给出“接住哪句、下一句可以讲什么”。验收：真实模型分享 follow-up 接住率 ≥90%（人工标注 50 条）。
7. **问句/意图统一分类器**：`amo_understanding.build_smart` 与 `amo_question_guard._category/_answered` 共用一份分类定义（规则+可选小模型，`auto` 为默认）；`answer()` 从“整条替换”改为“先答、再补状态”（append）；无法回答时发 `safe_reply` 前先检查候选是否其实已答。验收：问句探针未答 ≤2%。
8. **语义重复的跨轮窗口**：从“最近 5 条/0.9”升级为“同一 intent 的 30 分钟去重 + 24h 主题冷却”；主动消息生成前查 `recent_proactive_texts(30)`, 而不是 2-3 条。

### P2（验收与观测，持续）

9. **真实模型回归**：把 `real_llm_layer` 从“人设+snapshot”升级为**生产完整 prompt（含分享台账/状态块）**，跑 100–200 轮；报告必须同时给“守卫前/守卫后/真实模型”三列，禁止只用 mock 证明修复。
10. **生产采样指标**（只读 SQL/日志，不改代码）：`同一 intent 30min 重复率`、`问句答案命中率`、`分享 follow-up 接住率`、`通用兜底率`、`空/动作-only 率`、`主动消息同分钟>1`；直接进 `daily_report`。

### 明确不要做

- 不要继续“出一个线上样例加一条正则/一个固定句”；本轮证据显示补丁之间已经开始互相打架（`_attach_last_line` 换掉正确短答、`_prefer_answered_candidate` 漏新池、`amo_part_dedupe` 写了没接）。
- 不要把“提示词里再写一条禁止”当修复：`llm.catch_answer`（`amo_prompt_registry.py:466`）已经写了“接住他最后一句/不许答非所问/不许换对象”，真实模型仍失败；说明需要出口校验，不是再写一条。
