### 1.2 证据分级

1. **A 级（生产事实）**：messages 原表、astrbot.log 发送/守卫日志。能直接证明「线上发了什么」。
2. **B 级（真实模型探针）**：real_llm_layer.json。system prompt 只含人格 + 官方 snapshot + 日程，不含生产完整提示词，因此只能证明「基础人格 + 状态下模型会怎样」，不能替代生产。
3. **C 级（mock/仿真）**：daily_report / share_report（已由 task-5/7/10 覆盖），本报告只在需要对比时引用，不作为结论主证据。
4. **D 级（代码静态）**：快照行号，证明「机制上为什么会这样」，不等于线上频率。

### 1.3 关键口径

- **忘记刚说的话**：A 在过去 ≤2 轮 / 5 分钟内明确说过的事实或情绪，B 在下一轮否认、答成另一件事，或问已经答过的问题。
- **重复问同一问题 / 重复催问**：同一 intent（nudge/meal/goodnight/photo/分享）在 24h 内 ≥3 次，或 120s 内 ≥2 条近似（difflib ≥0.5）；整句重复指归一化空白/标点后相同或相似 ≥0.9。
- **与历史记忆矛盾**：同一对象（人/物品/金额/关系/地点）在两条 active 记忆、或记忆与日程/钱包/原话之间，状态不可同时成立。
- **称呼/关系错**：称呼与 profile/人设包不一致；把人名、关系标签、同伴对象认错；第三人称自称「你美丽的老婆」。
- **人设崩**：违反基础人格明文（不写动作旁白、不阴阳、不重复、不客服腔），或使用被 PromptRegistry 明令禁止的句式。
- **运维/质检/调试话术**：报错/服务器/接口/权限/软件崩了/超时/网络/面板/质检/重写/数据库/日志/token/模型/插件/后台/配置/上下文/收到你后来 等词出现在私聊文本里。
- **报账式数字**：非必要时报出精确金额、余额、等待分钟、价格，或「花了 N 元 / 卡里还有 N / 等了 N 分钟」句式；含中文数字（十五/二十/三百）。
- **姓名/物品误判**：出现名单外人名、名单内人名张冠李戴、物品状态（冷热/买没买/价格/颜色/款式）与素材或上一条冲突、文本被确定性改写弄坏。

### 3.1.2 频率与分布

- 生产 raw 窗口 3 天内至少 3 次「刚说过就被否认/改口」（11-19 视频 44 秒、11-18 食堂同轮、11-22 家 vs 商场）。

### 3.1.4 根因

1. **上下文窗口太短且是软约束**：10 行/8 行/1200 字，连续多段主动消息 + 多话题时，44 秒前的自己发言就可能被挤出「最后 8 行」；_bot_initiated 只是单槽、只保留 200 字、只软提示，没有「刚才说过 X，本轮禁止否认 X」的硬校验。
2. **没有「自我状态」对象**：reply 侧只有 recent、memory、state，没有「她上一轮说了什么/答应了什么/正在做什么」的结构化事实；主动消息、回复、日记三套各自记，互不校对。
3. **critic 口径太粗**：bigram 重合即通过，无法发现语义否定；prompt 里的 catch_answer（amo_prompt_registry.py:466-481）只是软规则，模型可违反且没有二次复检。
4. **人格设定与提示词鼓励「即时情绪」**：追问样例「你美丽的老婆晾这儿」让她在没上下文时也倾向复读情绪，而不是先对齐事实。

| amo_grounding_critic.py:35-48 | 同 3.1：bigram 重合即通过 | 「别生气」→「我哪生气了」含「生气」，误判接住 |

### 3.9.4 根因

1. **共情是软提示，不是可验证状态**：没有「用户上一句情绪标签」→「回复第一句是否回应」的检查。
2. **critic 口径粗**：bigram 重合无法区分「回应情绪」和「否认情绪」。
3. **人设/状态让她优先讲事实**：她正在气剧情，模型把「我哪生气了」当成解释事实，忽略了用户是在哄她。

## 4. 记忆—人设链路总图与失效点

写入侧（5 个写者）：
- 聊天回复 → amo_memory_context 召回 → 回复后写 messages（不作为长期事实）
- 里程碑（amo_runtime_tick:456，LLM 总结，tier=2）
- 每日总结（amo_runtime_tick:542，LLM 总结昨天，tier=2）
- 日记/日程事实（amo_schedule/日记模块：activity/event/fact/finance/milestone，tier=0-2）
- 财务/事件/社交见闻（amo_memory_data：finance_long_expense/permanent/event/social_news）

存储侧：amo_data.memories（917 行 / active 770），带 kind/subject/status/superseded_by 字段，但只有 imported_memory 等少数路径使用 supersede；里程碑/日记/财务没有统一 conflict key。

召回侧：memory_hooks.should_recall（私聊每轮）→ hub/data recall（top N）→ rerank → amo_memory_context._recall（limit 6、预算 1200、单条 240）→ _recall_format（[今日]/[昨日] 标签 + 强制「老公：」前缀）→ 注入【关于X的记忆】。

出站侧：reply_pipeline（fact_guard/scene_consistency/tone/repetition/purchase/reply_gate/grounding critic）→ _send_to_umo（anti_nag/purchase_guard/segment/repeat_guard/gateway 去重频控）→ 发送。

失效点编号：
- F1 写入无冲突裁决（3.3）
- F2 记忆是 LLM 二次总结，错误会被固化（3.3）
- F3 旧关系记忆（主人 145 条）未迁移，且被强制加「老公：」（3.4）
- F4 近聊/记忆窗口过短（10 行/8 行/6 条/1200 字）（3.1）
- F5 自我发言/自我承诺没有硬清单（3.1）
- F6 追问只有 previous_text 单状态，去重窗口短（3.2）
- F7 人设两套真源，动作旁白允许规则后置（3.5）
- F8 系统通知/工具错误直达私聊，无话术过滤（3.6）
- F9 精确数字多入口，无 approximate-only 出口（3.7）
- F10 确定性改写按词替换、无回读校验（3.8）
- F11 姓名/物品 grounding 只收口不前置（3.4/3.8）
- F12 分段引擎把旁白单独发，放大表演感（3.5）
- F13 情绪接不住：共情只靠软提示，critic 用 bigram 误判（3.9）

## 5. 统一根因

**她的「记忆/关系/人设/系统话术」没有单一事实源，也没有出站语义闸门。**

1. **事实源分裂**：回复、主动消息、日记、里程碑、财务、系统推送五条链路各自生成事实；记忆库是 LLM 对聊天的二次总结，不是事实抽取；钱包/衣柜/日程/记忆四个权威互相不知道对方。
2. **状态没有对象化**：「刚才说了什么/答应过什么/正在做什么/同伴是谁/买没买/多少钱」都只以文本片段散落在 recent、memory、pending、kv 里；没有可查询、可校验的结构化状态。
3. **改写链过长且不可逆**：从生成到出站经过 >10 道正则/LLM 重写（road_home、scene、tone、purchase、repetition、anti_nag、part_dedupe、voice…），每一步只保证「本步目标」，没有整体语义复检；「还在车上上」「米白色米白色」「收到你后来」都是链式改写的副产物。
4. **人格/禁语只靠 prompt**：基础人格与 PromptRegistry 冲突；禁语没有出站过滤器；系统话术没有黑名单。
5. **反馈回路会自我强化**：07:30 的 7 连发被写成「被晾在一边」的里程碑 → 下次召回让她更委屈/更催；649/985 被写成里程碑/每日总结 → 下次更可能报账。错误一旦进记忆，会被当成「她的真实经历」越滚越像真的。

## 6. 统一规则（建议，按优先级）

> 以下规则是审计产出，不含任何代码修改；供后续 fix 任务拆解。验收均可用只读 DB/日志 + 272 轮真实探针复跑。

### P0（先堵住用户能直接看到的破绽）

**R1 系统话术零进私聊**
- 规则：任何 source=system/push/reminder 的文本，默认只进面板/管理命令；确需私聊时，必须经「人话模板」转换，禁止出现：质检、重写、面板、报错、服务器、权限、接口、超时、软件崩了、网络、收到你后来/那句、数据库、日志、token、模型、插件、后台、配置、上下文。
- 代码位置：amo_diary_audit.py:699（notify 改为只写面板或增加 humanize）；amo_outbound.py 增加 system_phrase 黑名单（命中→drop 或改人话）；amo_prompt_registry 的【不报后台】扩展为完整词表。
- 验收：日志 7 天内 proactive/segment 系统词命中 = 0；【日记质检】不再进 messages 表。

**R2 精确数字/报账 zero**
- 规则：私聊只允许 approximate：余额说「四千出头/三千多」；价格说「九百多/小一千」；不许报「卡里还有 4072」「就是985」「等了十五分钟」「花了649元」；购买/消费结论必须来自钱包/衣柜记录，禁止「你说买不买」。
- 代码位置：amo_runtime_context.py:487 去掉 %.2f，复用 money_fact_line 的 approximate；amo_purchase_guard 扩展 price/balance/duration 正则；persona_pack money 段加禁语；出站加数字过滤器（金额/余额/分钟）。
- 验收：7 天报账式数字 = 0；记忆注入金额只允许「约X」。

**R3 出站语义复检（破坏性改写后）**
- 规则：任何确定性改写（road_home/scene/tone/purchase/repetition/anti_nag/media strip）后，必须做一次整体复检：地点不矛盾、人物不换、物品状态一致、无残句（「上上」「米白色米白色」）、无系统词；不通过则回退原文或改写为安全短句。
- 代码位置：amo_transition.py:1999（修裸词替换 + 状态回读）；amo_state_consistency.py:589-702（已有 demote/strip/dedupe，扩展为统一 postcheck）；amo_message._send_to_umo:1005 前加 postcheck。
- 验收：注入「我到家了，瘫在沙发上」在 on_road 状态 → 输出必须语法完整、不得出现「还在车上上」；「米白色」不得连续重复。

**R4 不否认自己刚说的话**
- 规则：回复前强制把「她最近 3 条自己发的话」作为不可否认事实清单（硬约束，不只 prompt）；若用户问的是她刚说过的话题，必须沿用同一对象/说法；禁止「什么视频/我没说/不是你说」式反问。
- 代码位置：amo_llm.py:542 附近增加 self_recent_texts；amo_grounding_critic.issues 增加「与最近 self 文本冲突」检查；reply_pipeline 出站前复核。
- 验收：构造 20 条「她说 X → 用户问 X」样本，否认率 0；构造 20 条「用户表达情绪 → 她第一句」样本，先接情绪率 100%；生产 7 天同类事故 0。

### P1（结构性，决定长期质量）

**R5 记忆事实账本（单一真源）**
- 规则：把「人/物品/金额/关系/地点/承诺」做成结构化 fact ledger：subject_key、state、value、source、valid_from、supersedes；里程碑/每日总结只能写「叙事摘要」，不能直接写事实；事实必须来自 wallet/wardrobe/schedule/messages 的抽取；同 key 新值 supersede 旧值，active 最多 1 条。
- 代码位置：amo_memory_bridge._write_memory_checked、amo_runtime_tick 里程碑/总结、amo_schedule 日记事实统一走 ledger。
- 验收：开衫只剩 1 条 active 事实（买/没买 + 价格）；余额只有钱包一个来源；145 条「主人」记忆迁移/归档为「旧关系·已废止」。

**R6 旧关系记忆迁移**
- 规则：把 145 条「主人」active 记忆批量标 superseded/archived，或在 _recall_format 中过滤；禁止把 user 记忆无条件加「老公：」前缀（至少对含「主人/宠物/调教」的旧记忆跳过）。
- 验收：召回池里「主人」记忆 = 0；不出现「老公：主人…」。

**R7 人设单一真源**
- 规则：基础人格「不写动作旁白」为最高优先级；删除/收窄 PromptRegistry llm.rule.core 的「允许括号动作」；动作旁白 ≤5% 消息、0 条独立动作消息；禁语加入「你们男人」「你美丽的老婆」「收到你后来」；金钱观补「不报精确数字/不把消费决定推给他」。
- 代码位置：amo_prompt_registry.py:482-487、:173-182、:466-481；persona_packs/gentle-playful.json forbidden；segment_engine 禁止单独动作段。
- 验收：动作旁白 ≤5%、独立动作段 0；被禁句式 0。

**R8 追问/主动消息持久状态**
- 规则：nudge/photo/meal/goodnight 每类按 uid 记录 last_sent_at、count_today、last_intent_text；跨入口共享；同一 intent 24h ≤3、2h ≤1；追问样例删除「你美丽的老婆」，改成与人设一致的一句；多入口统一走 OutboundGateway（已部分完成，需验证）。
- 验收：07:30 类 7 连发 0；24h 同 intent >3 = 0。

**R9 姓名/物品 grounding 前置**
- 规则：proactive/微事件生成前，把「素材原文 + ROSTER + RELATION_LABEL + 当前 wardrobe/shopping 状态」作为不可编造上下文；出站 strip_unbacked_names 对 proactive 也生效；物品状态以 wardrobe/wallet 为准。
- 验收：名单内张冠李戴 0；「陪你逛」类同伴误判 0；开衫价格/买没买与账本一致。

### P2（体验/长期）

**R10 记忆卫生**：bot_media 占位记忆（9 条自拍）不进召回；相对时间词统一补日期；运维/后台记忆定期归档；里程碑去重（同日同对象只留 1 条）；对「因自己刷屏产生的委屈/被晾着」里程碑加抑制（不能把系统行为写成用户冷落）。

**R12 监控指标**：把下列指标做成周报（只读 SQL/log）：动作旁白率、独立动作段数、系统词命中、报账数字、重复组、矛盾记忆数、自我否认率、姓名误判率、用户记忆投诉数。
