# 人设功能使用指南

> 2026-11-24 面板改版后重写。人设页签现在是四张卡：**人设名片 / 候选语料 / 语气预览 / 导入导出**。

人设不是「再写一段提示词」，而是一份可以整包替换、可以慢慢进化的**人格包**：

- **pack.json**：内核、称呼、关系语气、语言规则、金钱观、禁语、语料（只读的基础卡）；
- **state.json**：从候选里批准进来的「进化语料」、权重、快照（会随使用变化）。

每条回复都会把当前人设包拼成一段【人格包】，连同 3 条语料一起塞进系统提示词；所以改人设 = 改她下一句怎么说话，不用重启。

---

## 1. 面板在哪

AstrBot 面板 → 插件 → **我能永远陪伴你**（`Astrbot_amoupup_forever`）→ 顶部 **人设** 页签。

- 面板发过新版后，第一次打开请 `Ctrl + F5` 强制刷新，不然可能还看到旧的缓存页面。
- 人设改动**不需要重载插件**，切换/通过后下一条消息就生效。

---

## 2. 人设名片（第一张卡）

| 位置 | 含义 |
|---|---|
| 头像 + 名字 | 当前人设包的 `name`（默认「温柔娇泼」） |
| 名字下面一行 | `card.core`，人设内核，比如「认定你、护短、要强、怕失去」 |
| 右上角胶囊 | 当前人设包 id，比如 `gentle-playful`；这个 id 就是 `/人设 切换 <id>` 里用的 |
| **语料** | 人设包 `corpus` 自带的条数（默认 25） |
| **进化** | 已经批准、写进 `state.corpus_evolved` 的条数 |
| **待批** | 候选区里等着你点「通过」的条数 |

**切换人设**：下面那排胶囊，点一下「office-lady」就切过去，当前那个前面会打 ✓。

- 切换**不会覆盖**原来那份包，切回去还是原样；
- 切走以后不会在后台继续学习，切回来接着用原来的 state；
- 面板没有「删除人设」按钮，要删就手动删 `persona_profiles/<id>/` 整个目录（删之前先备份）。

## 3. 候选语料（第二张卡）

候选 = 她「学到的新说法」，**批准前完全不生效**。

- 点某条右边的 **通过**：这条从候选移到 `state.corpus_evolved`，同时「进化 +1、待批 −1」，下一轮回复就可能被抽到。
- 空的时候会显示「没有待批准的新语料」，并提示怎么手动加。
- 面板只能**通过**，没有「拒绝/删除」；不想要的候选可以放着不管，或者手动改 `state.json`。
- 上限：候选最多 20 条（超了自动丢最旧的）；已批准的进化语料最多 100 条。
- 每次加候选 / 批准之前都会自动生成一份 `snapshots/` 快照，用来回滚。

**手动加一条**（管理员，在聊天里发）：

```text
/人设 候选加 老公你以前不这样，我有点害怕
```

然后回面板点「通过」。

### 自动进化（她自己的例句池，2026-11-24 A 阶段）

> 默认 **关**。打开后也只「入池」，**不会**自动写进人设、不会自动通过候选；先观察采集质量。

- 开关在名片里「自动进化 开/关」；配置项 `persona_auto_evolve` 默认 `false`。
- 只学**私聊**、只学**聊天回复**：主动消息、系统推送、照片/语音、群聊、发送失败都不采集。
- 她这条回复真正发出去后，把最终文本 + 当时的真实 `scene`（日程 zone）/`mood` 暂存；等你下一条消息进来，按你的反应判：
  - 正向（`哈哈/可爱/喜欢你/乖/好呀/嗯嗯/真棒`，或继续话题 ≥4 个汉字且不是命令句）→ 过滤后入池；
  - 负向（`滚/烦/闭嘴/无语/随便/别说了/换一个/重说/不听`、1–2 个字敷衍）→ 丢弃；
  - 10 分钟没回 / 中性 → 丢弃，不学。
- 入池前过滤：6–40 个汉字、不含禁语、不含 AI/技术词、不是括号动作模板、和你最近的话/固定池/已有语料相似度 <0.8、极端情绪不学、每天最多 `persona_evolve_daily_cap`（默认 3）条。
- 池上限：每意图 `persona_style_pool_per_intent`（默认 6）、总 30；30 天没被抽中按天 ×0.98，低于 0.5 进 `style_archive`（不删）。
- 注入：私聊优先她自己的池（当前意图最高分 2 条），**池空回落固定 33 条**，提示词前缀「你以前这样说过（只学语气，不要逐字重复）」，总增量 ≤120 字。
- 「最近自动进化」卡可看她最近入池的句子（场景 + 句子 + 来源），每条能**撤销**；每次入池前自动写 `snapshots/` 快照。
- A 阶段只入池、不写候选；B 阶段（自动候选/自动通过）等观察 3 天且你明确说开再做。

## 4. 语气预览（第三张卡）

用来回答一个问题：**「她这会儿到底拿到了什么提示词？」** 只读，不改人设、不发消息、不写记忆；只有点「生成预览」才会真正去取。

- **场景 scene**：聊天时自动取当前日程地点（`home_bed`、`office`、`scenic`…）；手填时写英文 key，如 `quarrel`、`sick`、`makeup`。
- **情绪 mood**：自动取当前主导情绪（如「委屈」）；手填中文即可。
- 快捷芯片：**通用 / 吵架 / 生病 / 认错 / 撒娇 / 被夸 / 吃饭 / 安慰**，点一下只**填好** scene + mood，还要再点「生成预览」才会请求；改参数会作废上一次结果，避免旧结果看起来像新场景的。
- 下方会显示：命中的语料条数 + 完整的人格包提示词（内核、称呼、关系语气、语言、金钱观、公开场合、动作、绝不说、3 条语料）。

预览的匹配规则（和真实回复一致，2026-11-24 A1 起）：

1. `scene` 完全相同的语料 +2 分；
2. `mood` 是语料 mood 的子串 +1 分；
3. `scene` 是 `"" / general / manual` 的通用/进化语料 +1 基础分（保证以前永远匹配不上的手动语料能补位）；
4. **通用/进化语料最多占 3 槽中的 1 条，并固定放在第 3 条**；只有整个包一条非通用语料都没有时才放宽；
5. 同一句短期内被抽过会排到后面（`last_used`），防连续复用；
6. 不指定 scene/mood 时**仍会按分数补位**，但通用语料同样只占 1 条。

⚠️ 预览只包含「人格包」这一段，不包含运行时的状态/日程/记忆/守卫块，所以和实际 system prompt 不会逐字一样，但人设部分是完全一致的。

## 5. 导入 / 导出（第四张卡，默认收起）

### 导出当前

点「导出当前」会把**整包**填进文本框：

```json
{ "pack": { ... }, "state": { "corpus_evolved": [], "candidates": [], "snapshots": [] } }
```

- **复制 JSON**：复制到剪贴板，方便发给自己/存档；
- **下载 .json**：存成 `persona-<id>.json`。

### 导入人设包

文本框粘贴 JSON →「导入人设包」；或者「从文件导入」选一个 `.json`。

- 可以粘**裸 pack**（顶层就是 `id/name/card/corpus`），也可以直接粘**导出的整包**（会自动取里面的 `pack`）；
- 校验：必须有 `id`、`name`、`card.core`、`corpus`；`id` 只能是字母/数字/`_`/`-`，最长 32 位；每个 scene 最多 5 条、总数最多 100 条；
- **id 已存在会被拒绝**（不会覆盖现有人设）——想升级同一个人设，把包里 `id` 改成 `xxx-v2` 再导入；
- 导入后**不会自动切换**，回名片点新的人设胶囊才会用上。

### 换角色 / 备份的正确姿势

1. 先在当前人设点「导出当前」→「下载 .json」，留一份原样；
2. 改 JSON：`id` 换个新的、`name`、`card.core`、`corpus` 按新角色写；
3. 导入 → 名片里点新胶囊切换；
4. 用「语气预览」选几个场景看提示词，不满意就切回原来的。

整目录备份：把 `plugin_data/Astrbot_amoupup_forever/persona_profiles/` 整个拷走即可（`pack.json` + `state.json` + `snapshots/` 都在里面）。

## 6. 聊天命令（管理员）

| 命令 | 作用 |
|---|---|
| `/人设` | 看当前 id、可选 id、候选数 |
| `/人设 切换 <id>` | 切换到某个人设（旧状态保留） |
| `/人设 候选` | 列出待批准候选（最多显示 10 条） |
| `/人设 候选加 <一句话>` | 手动加一条候选 |
| `/人设 通过 <序号>` | 批准第 N 条候选（序号从 0 开始） |

非管理员发这些命令会回「只有管理员才能改人设」。

## 7. 人设包长什么样

```json
{
  "schema_version": 1,
  "id": "gentle-playful",
  "name": "温柔娇泼",
  "card": {
    "core": "认定你、护短、要强、怕失去",
    "address": { "user": "老公", "self": "我" },
    "registers": { "partner_safe": "撒娇、使唤、泼辣、炫耀" },
    "language": { "rules": ["日常请求直接说，不用「能不能」缓冲"] },
    "money": "不拜金、不比别人、不索取",
    "public": "可叫老公，不性暗示",
    "forbidden": ["窝囊废", "你很烦"]
  },
  "corpus": [
    { "scene": "sick", "mood": "示弱", "text": "能不能给我倒杯热水" }
  ],
  "rules": { "refusal": "按理由分档", "public_no_sex_hint": true }
}
```

| 字段 | 必填 | 进不进提示词 | 说明 |
|---|---|---|---|
| `id` | ✅ | — | 目录名 / 切换用的 id，字母数字 `_` `-`，≤32 位 |
| `name` | ✅ | 面板显示 | 人设名 |
| `card.core` | ✅ | 【人设内核】 | 一句话内核，最重要 |
| `card.address.user/self` | — | 【称呼】 | 他叫你什么、你自称什么 |
| `card.registers.*` | — | 【当前关系语气】 | 多档关系语气；**目前固定取 `partner_safe`** |
| `card.language.rules` | — | 【语言】 | 说话规则数组，会全部拼进去 |
| `card.money` | — | 【金钱观】 | |
| `card.public` | — | 【公开场合】 | |
| `card.forbidden` | — | 【绝不说】 | 禁语；**最多取前 20 条** |
| `corpus[]` | ✅（可为空数组） | few-shot | `text` 必填，`scene` 默认 `general`；每 scene ≤5 条、总数 ≤100 |
| `rules` | — | ❌ | 目前是保留字段，不参与拼提示词 |

> `card.language.openers / particles` 也还是预留字段，当前不参与拼接。

## 8. 它是怎么影响回复的

1. 每条回复组装 system prompt 时，`_persona_pack_blocks()` 会取**当前人设包 + 已批准语料**，生成 `【人格包】…` 一段；
2. 取语料用的 `scene` 是当前日程的 `zone`（如 `home_bed`），`mood` 是当前主导情绪；
3. 私聊还会额外注入一组例句：优先她自己池子里当前意图最高分的 2 条；池空时回落固定 33 条（`style_examples.json`），按你这句话的意图（累/夸/想你/吃/在哪/撒娇…）取 2 条，只学语气；
4. 语料是 **few-shot**：只学语气和句式，规则里明确要求「不要逐字复用」；
5. 群聊不注入例句池，人设包本身照常注入。

**和 AstrBot 人格的关系**由配置 `persona_source` 决定：

| 值 | 行为 |
|---|---|
| `pack`（默认，推荐） | 只用本插件人设包，**不读** AstrBot 人格提示词，避免「通用 AI 助手」腔混进来 |
| `merge` | AstrBot 人格作补充，冲突时以人设包为准 |
| `astrbot` | 沿用旧行为，AstrBot 人格优先 |

不管选哪个，AstrBot 人格的**名字**仍会用于称呼；配置里的「人格补充设定」(`persona_extra`) 会追加在人格后面。

## 9. 四个常见操作

### ① 只想让她某个场景更像她

1. 聊天里 `/人设 候选加 <她真会说的那句话>`（一次一句，别写解释）；
2. 面板「候选语料」点「通过」；
3. 「语气预览」点对应芯片（比如「吵架」），确认这条进了提示词；
4. 不满意就再补一条——语料只影响语气，不会改人设卡。

### ② 完整换一个角色

导出 → 改 `id`/`name`/`core`/`corpus` → 导入 → 名片里切换 → 预览验证。

### ③ 备份 / 搬家

- 单个人设：导出当前 → 下载 `.json`；
- 全部人设：拷 `plugin_data/Astrbot_amoupup_forever/persona_profiles/`（备份插件数据目录时本来就会带上）。

### ④ 误批准了想回滚

`persona_profiles/<id>/snapshots/` 里每次操作前都有一份 state 快照：

1. 先停插件 / 至少别在聊天；
2. 把目标快照文件复制成 `state.json`（覆盖前把现在的 `state.json` 另存一份）；
3. 回到面板刷新，候选/进化数字会回到那一刻。

## 10. 常见问题

**Q：点了「通过」，为什么聊天感觉没变？**
A：语料是 few-shot，只在一轮回复里抽 3 条，作用是语气微调；人设卡（内核/语言/禁语）优先级更高。想明显改，去改 `card.core` / `language.rules` / `forbidden`。

**Q：预览里明明有 3 条语料，聊天里却没出现？**
A：聊天时 `scene` 取的是当前日程 `zone`（英文 key），不是面板里手填的场景；预览只验证「人格包」这一段，实际 system prompt 还有状态、记忆、守卫等块。

**Q：导入提示「这个 id 已存在」？**
A：不会覆盖现有人设。把包里 `id` 改掉（如 `gentle-playful-v2`）再导入。

**Q：切换人设后她说话没变？**
A：先 `Ctrl+F5` 刷新面板确认切过去了；再确认配置 `persona_source` 没有被设成 `astrbot` 把人格包盖住；人设包缓存按文件修改时间失效，正常下一条消息就生效。

**Q：候选会自己长出来吗？**
A：A 阶段还不会：打开「自动进化」后，她自己的句子只进**例句池**（面板「最近自动进化」可见、可撤销），不写候选；候选仍来自 `/人设 候选加`。B 阶段才会入候选，且自动通过默认关。

**Q：禁语写了却没生效？**
A：`card.forbidden` 只取**前 20 条**；超过 20 条的排在后面的不会进提示词。

**Q：为什么 `registers` 里写了 `friend`/`colleague` 没效果？**
A：当前固定用 `partner_safe` 这一档，其它档是给以后按关系切换预留的。

## 11. 文件位置

```text
plugin_data/Astrbot_amoupup_forever/persona_profiles/
  gentle-playful/
    pack.json        # 基础人设（导入/导出就是它）
    state.json       # 进化语料、候选、例句池/归档、last_used、快照索引
    snapshots/       # 每次候选/批准前的 state 备份
```

- 默认包参考：`persona_packs/gentle-playful.json`（随插件发布，只读）；
- 当前用哪套：kv `persona_active`；
- 例句池：`persona_packs/style_examples.json`（33 条，只用于私聊语气）。

## 12. 边界

- 基础卡（内核/称呼/语言/禁语）**不会被学习改写**，只有你点「通过」才会加语料；
- 人设按**安装实例**隔离，不按聊天对象切换；每个人装一份插件、一份 `persona_data`，互不影响；
- 记忆（关系、日记、聊天记录）不在人设包里，切人设**不会**重置记忆；
- 面板的改动写的是 `plugin_data` 下的文件，插件升级/重装不会被覆盖（但重装前仍建议备份）。
