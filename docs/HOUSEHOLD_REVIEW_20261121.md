# 同居功能评审（2026-11-21）

## 总体判断

主干设计是合理的：`amo_household.scene_at()` 是唯一在场判定，三档（分居/半同居/同居），
apart 档文案一律返回空串回落到 7.5.9 原文（黄金零漂移），命令有管理员门槛。

但它只解决了「他在不在家」，没有解决「他是谁」——这正是你看到的「神秘的他」。

## P0（已修）

| 问题 | 修法 | 位置 |
|---|---|---|
| 小日记里的「他」没有钉死是用户本人，模型可能写成「有个男人」「神秘的他」或第二个人 | 日记三套规则（独处/在家/约会）都加【他是谁·最高优先级】：「他」只能是老公/用户本人，不许第二个男性 | amo_diary_guard.py |
| 「他出差」无法表达：提示词写了「他上班/出差时不在」，但判定只看 9:00-18:30 | 新增 partner_away 覆盖 + `/居住 出差` `/居住 回家`（管理员）；scene_at 优先判出差 | amo_household.py / amo_commands.py |
| 521 行模块零测试 | 新增 20 例：三档矩阵、上班时段、周末、半同居窗口、出差覆盖、迁移门槛、过夜幂等、apart 文案 | tests/test_household.py |

## P1（已修）

| 问题 | 修法 |
|---|---|
| 日记的「他在不在家」只看 21:00-22:00 一块：白天在家、晚上出门会整篇写错 | 改扫当天所有块，任意一块他在家就按在家规则 |

## P1（未修，等你定）

1. 节假日/调休：partner_at_work 只看 weekday，法定假日（周三）会判他上班，调休周六上班会判他在家。要不要接 day_type/节假日？
2. 出差没有结束时间：现在只有手动开关，要不要 `/居住 出差 3天` 自动回来？
3. 聊天边界（wording boundary）还没写「他=用户」，只有日记写了；要不要同步？
4. 半同居过夜计数会把 22:00-23:00 追剧块也算一夜（按天去重，影响小）。

## P2（优化）

1. scene_at 每块都读 kv，日记逐块调用会重复读库，可加进程内缓存；
2. count_night 用 start>=22:00 判过夜，建议改成「睡眠块或 23:00 后」；
3. 文档里 L0/L1/L2/L3 与实现三档不一致，建议统一。

## 一个需要知道的优先级

scene_at 里「约会窗口」优先于「出差」：如果日程里明确有约会事实，即使标记了出差，也会判面对面。
这是「事实优先于状态」，合理，但请在出差时把约会日程一并取消。

## 第二轮：P1/P2 全修 + 称呼可配置（2026-11-21 下午）

用户口径：日记里的「他」= 用户本人；叫他什么由用户让她喊的称呼决定（默认老公）。

| 项 | 级别 | 处理 |
|---|---|---|
| 称呼写死「老公」 | P0 | 新增配置 person_ref_title（默认老公）：person_ref/normalize、日记规则、同居边界文案全部改用配置值；schema 271->272 |
| 节假日/调休 | P1 | scene_at 的「他上班」加入法定假日判断（is_holiday，interop CN_HOLIDAYS/可编辑日历） |
| 出差没有结束时间 | P1 | set_away 支持天数（until），到期自动回家；/居住 出差 3天 |
| 聊天边界没写「他=用户」 | P1 | wording(boundary) 两档都追加【他是谁】用户本人 + 称呼 |
| 过夜计数偏松 | P1/P2 | 22:00 改成 23:00 起算，22 点追剧块不再算一夜 |
| 文档 L0-L3 与三档不一致 | P2 | 统一为三档命名 |
| scene_at 缓存 | P2 | 不做：kv 是单行索引查询，进程内缓存会有脏读风险（测试/外部改 kv 绕过），收益小于风险 |

测试：test_household 增至 26 例，新增 test_person_ref_title 11 例。

## 第三轮：P0/P1/P2 全修（用户要求）+ 称呼可配置

- P0：称呼不再写死「老公」——新增 person_ref_title（默认老公），日记/日程/同居边界共用；
- P1：节假日不算他上班；出差支持天数到期自动回家；聊天边界补「他=用户本人」；过夜 23:00 起算；
- P2：文档三档命名统一；scene_at 缓存评估后不做（脏读风险大于收益）；
