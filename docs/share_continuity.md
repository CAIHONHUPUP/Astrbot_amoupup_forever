# 分享连续性设计（待确认，未实现）

## 目标

她分享视频/图片/事情后，用户回应时她必须接住，并且：

- 对象一致：她发的是猫，后续不能变狗；
- 角色一致：是她分享给用户，不是让用户去看他自己发的；
- 状态一致：在家/在外、正在吃什么、有没有真的带媒体；
- 不重复分享：同一件事不能过一会儿又当“新发现”发一次；
- 句子完整：不能把“等会儿弄点吃的”和“自己煮的面”硬拼。

## 数据

分享台账（kv 或 state）：

```json
{
  "topic": "猫",
  "type": "video",
  "at": 1795240000,
  "text": "一只猫跟着节奏摇头",
  "pending_reaction": true,
  "media_attached": true
}
```

状态事实来自现有 current_activity / state：地点、正在做什么（吃面/做饭/路上）。

## 生成流程

1. 她分享时写台账；
2. 用户回复时，把三条事实一起给模型：
   - 你刚分享过：猫视频（19:02）
   - 你现在：在家吃面
   - 他刚说：哈哈哈
3. 提示词要求：先接住用户这句，再延续自己刚分享的事；不许重新分享、不许换对象；
4. 生成后 critic 检查：
   - 对象是否一致（猫/狗）；
   - 状态是否一致（地点/动作）；
   - 是否答非所问；
5. critic 失败 → 重写一次；仍失败 → 确定性守卫只删错句，不换模板。

## 需要确认

1. “刚才吃的面”是真实状态还是模型编的？如果没在吃面，不应编。
2. 同一对象/同类内容重复分享冷却：30 分钟或 2 小时？
3. 兜底偏好：
   - 删错句，只留“我看了刚才那个视频，挺好笑的”；
   - 或允许改写成“吃面差点喷出来”这种具体句。
