# 人设自进化设计（未实现，仅方案）

> 2026-11-24。状态：**仅设计，没有任何运行代码改动**。等确认范围后再按 P0/P1/P2 施工。
>
> 触发问题：「能不能让她自己进化？我每次 `/人设` 不是让她像个演员吗？」

## 1. 为什么现在像“演员”

不是 `/人设` 这个命令的问题，是三层“台词来源”叠加：

| 来源 | 现状 | 问题 |
|---|---|---|
| 固定例句池 | 私聊每轮注入 `persona_packs/style_examples.json` 里 2 条（共 33 条人工句），prefix「像她会说的话，只学语气」 | 参考的是**别人写的台词**，只能照腔调演 |
| 手动语料 | `/人设 候选加 <你写的句子>` → 通过 → `state.corpus_evolved` | 台词是**你写的**；而且 `scene="manual"` 永远匹配不上日程 zone，批准后基本抽不到 |
| 人设卡 | `card.core / language.rules / forbidden` | 只读、不进化（这是对的，防止跑偏） |

另外 `state.weights` 从初始化后**从未被读取**，也就是“权重进化”只留了字段，没有实现。

结论：现在不存在“她自己进化”，只有“你写台词 + 一套固定例句”。真正要解决“演”，得让 few-shot **来自她自己的真实输出**，并且用**你的反应**当奖励，而不是让她自己夸自己。

## 2. 目标与非目标

**目标**

- 她参考的例子，主要来自她真实说过、且你反应不错的句子；
- 语气会随相处缓慢变化（变短/变更软/更常用某些语气词），但不会突然换人；
- 全程可暂停、可撤销、可回滚，上限明确；
- 不增加每轮延迟（不额外调模型做判断）。

**非目标**

- 不改 `card.core / address / forbidden`；
- 不做“自由生长的人格”（一定会复读、漂移、自我强化）；
- 不学群聊、不学吵架/极端情绪时的句子；
- 不引入外部数据，全部本地。

## 3. 现状链路（施工锚点）

- 发送唯一入口：`amo_message._send_to_umo`（照片/语音/系统推送也走这里，需要按 `source/kind` 过滤）；
- 私聊例句注入：`amo_llm._compose_reply` 里 `style_block(text)`，位置在 system prompt 末尾（权重最高）；
- 语料注入：`amo_llm._persona_pack_blocks` → `prompt_block(active_pack, scene=zone, mood=dominant)`；
- 语料存储：`amo_persona_store`（`pack.json` / `state.json` / `snapshots/`）；
- 候选写入：只有 `amo_persona_store.add_candidate`，调用点只有 `/人设 候选加`；
- 检索：`amo_persona_pack.retrieve`（scene 完全匹配 +2、mood 子串 +1、前 3 条、不足按 index 补）。

## 4. 三层设计

### L1 她自己的例句池（解决“演”，优先级最高）

**采集**

1. `_send_to_umo` 成功发出后，如果是**私聊 + 聊天回复**（排除 proactive/系统/照片语音），把最终文本连同当前 `scene`（日程 zone）和 `mood`（主导情绪）暂存到 `state.pending_review`（只留 1 条，新的覆盖旧的）；
2. 你下一条消息进来、在生成回复之前判定反应（见 §5）：
   - 正向 → 这条进入 `style_pool`（按 `style_intent(text)` 分到 care/praise/miss/food/place/playful/daily/other），同时可进候选；
   - 负向 → 丢弃，并记一次 `evolve_stats.negative`；
   - 中性/超时（>10 分钟）→ 丢弃，不学。
3. 同一句只留一条（归一化后相似度 ≥0.85 视为重复）。

**使用**

- 新增 `learned_style_block(plugin, text)`：
  - 取当前意图下得分最高的 2 条；
  - 若该意图池为空，回落到现有 33 条固定池（保证冷启动不空窗）；
  - prefix 改成「你以前这样说过（只学语气，不要逐字重复）」；
- 注入位置不变（system prompt 末尾），每条 ≤40 字，最多 2 条，prompt 增量 ≤120 字。

**容量与衰减**

- 每个意图最多 6 条，总池最多 30 条；
- 每条带 `score`：被抽中一次 +1；连续 30 天没被抽中每天 ×0.98；低于阈值移入 `style_archive`（不删，可恢复）；
- 新句入池时若同意图已满，替换掉 score 最低的。

### L2 风格画像（不存原句，最不像演员）

- 每天一次（挂在现有 tick/日记任务里，不新增定时器）统计她最近 7 天发出的私聊句子：
  - 中位句长、语气词 top3、称呼使用率、问句率、叠词/emoji 率、平均分段数；
- 只写数字到 `state.style_profile`；
- 注入一句：「你最近说话：短句为主，常用『呀/嘛』，先接他的话再补一句」——由模板生成，不允许自由发挥；
- 作用：即使例句池没更新，语气也会跟着她近期状态走。

### L3 权重（可选，最后做）

- `corpus_evolved` 每条加 `hits` / `score`；
- 被抽中且反应正向 → score +1；负向 → −1；
- 检索排序从「分数 + index」改为「分数 + score 微调」（`+0.1 * clamp(score)`，不改变 scene/mood 的主导权）；
- 长期低分的归档，不进 prompt。

## 5. 奖励信号（关键，决定是进化还是自恋）

**只用规则，不调模型**（避免每轮多一次 LLM 调用和延迟）：

正向（满足其一，且不含负向词）：

- 明确正反馈：`哈哈/笑死/可爱/喜欢你/亲/抱/乖/好呀/嗯嗯/真棒`；
- 继续话题：≥4 个汉字、10 分钟内、不是命令句（不含 `换一个/重说/别/不要`）。

负向（任一）：

- `滚/烦/闭嘴/无语/随便/别说了/换一个/重说/不听`；
- 仅 1–2 个字的敷衍（`哦/嗯/。`）；
- 10 分钟内没有回复（视为冷场，不学）。

中性：其余全部不学。宁可少学，不要学歪。

## 6. 过滤器（入池前全部通过）

1. 文本长度 6–40 个汉字（去标点）；
2. 不含 `card.forbidden`、不含技术词/AI 腔（`作为/首先/总之/服务器/模型/接口`）；
3. 不含动作旁白、括号动作、URL、数字清单一类的“模板句”；
4. 与她现有语料、固定池、他自己最近说过的话相似度 <0.8（防复读、防学他说话）；
5. 只私聊；`group=True` 一律跳过；
6. 当前 mood 不是极端负向（生气/崩溃/绝望时说的狠话不学）；
7. 频率上限：每天最多 3 条入池、2 条自动进候选。

## 7. 自动候选 / 自动通过

- 入池的句子同时可以进 `state.candidates`，行里加 `source:"auto"`、真实 `scene`、`mood`；
- `persona_auto_approve=false`（默认）：还是要你在面板点通过（但句子已经来自她，不是你写的）；
- `persona_auto_approve=true`：满足「同一句被正向确认 ≥2 次、跨 ≥2 天」才自动通过，且每天 ≤2 条；
- 每次写入前 `snapshot("before_auto_evolve")`，面板可一键撤销到上一份快照；
- 候选/语料上限沿用：候选 20、进化语料 100、自动条目单独计数方便回滚。

## 8. 顺手必须修的检索问题

现状：`add_candidate` 固定 `scene="manual"`，检索永远不匹配 → 批准后进不了前 3 条（已实测：`home_bed/quarrel/sick/office` 四个场景，手动语料全部未命中）。

修法（与自进化配套）：

- 自动采集时写入**真实 zone**（如 `home_bed`），而不是 `manual`；
- `retrieve` 给 `scene in ("", "general", "manual")` 的条目 +1 基础分（低于精确场景 +2，高于无关的 0），保证通用语料在场景不匹配时能进补位；
- 补位顺序从“永远基础包优先”改为“先补 score 高的”，否则第 26 条之后的语料永远轮不到。

## 9. 面板与配置

面板（人设页）：

- 候选行加来源标签：`自动` / `手动`；
- 名片加一行「自动进化：开 / 关（今日 +N 条，最近一次 …）」+「暂停」；
- 「最近自动进化」列表（时间 / 句子 / 场景 / 来源），每条可「撤销」；
- 预览里标注哪 2 条来自她自己的池。

配置（`_conf_schema.json`，默认全部保守）：

| key | 默认 | 说明 |
|---|---|---|
| `persona_auto_evolve` | false | 总开关（确认效果前先关） |
| `persona_auto_approve` | false | 自动通过（需重复确认） |
| `persona_evolve_daily_cap` | 3 | 每天入池上限 |
| `persona_style_pool_per_intent` | 6 | 每个意图保留条数 |
| `persona_style_decay_days` | 30 | 未使用衰减起始天数 |
| `persona_evolve_groups` | false | 是否学群聊（默认否，不建议开） |

## 10. 分阶段

**A（先做，解决“演”）**

- L1 采集 + `learned_style_block` 替换固定池（空时回落）；
- 检索 +1 基础分 + 真实 scene；
- 只写入池，不自动进候选（零风险验证采集质量）。

验收：连续 3 天，私聊回复中「来自她自己池」的例句占比 ≥60%，prompt 长度增加 ≤120 字，复读率不升。

**B（自己进化）**

- 自动候选 +（可选）自动通过 + 面板开关/撤销；
- 写入前 snapshot、每日限量。

验收：一周后，候选里 ≥80% 是自动来源；你点「通过」的次数下降；没有出现“她天天说同一句”。任何一项不达标 → 关开关、回滚。

**C（可选）**

- L2 风格画像 + L3 权重/衰减；
- 用「复读率 / 平均句长 / 你的负向反应率」做 A/B（开 3 天 vs 关 3 天）。

## 11. 风险与放弃条件

| 风险 | 缓解 |
|---|---|
| 自我强化、越学越窄 | 相似度去重、每意图上限、score 衰减、固定池兜底 |
| 学到他说话的风格 | 只采集她发出的句子；与他近期文本相似度过滤 |
| 学到伤人的话 | 极端情绪不学；禁语过滤；只正向确认才留 |
| prompt 变长拖慢/变贵 | 最多 2 条 ×40 字；预览里可见增量 |
| 评估困难 | 先只观察不自动通过；用面板来源标记抽查 |
| 出错污染人设 | snapshot + 一键撤销 + 文件备份；基础卡永不被改写 |

放弃条件：开启两周内，复读率上升 >20%，或你的负向反应明显变多 → 关 `persona_auto_evolve`，恢复固定池（状态文件不删，可再开）。

## 12. 施工前要确认的事

1. 默认先只开 A（只学不用/只进池），还是一上来就 A+B（自动进候选）？
2. 自动通过要不要默认关？（建议关，观察一周）
3. 群聊是否学习？（建议永远关）
4. 面板需要「最近自动进化」列表到什么粒度？（句子 + 场景 + 时间 + 撤销，建议够用）
## 13. 和「手动候选三方向」的关系

之前提过三个修法方向，做了 A+B 之后的分工：

| 原方向 | A+B 之后 | 结论 |
|---|---|---|
| 1. 检索给 manual/general +1 基础分、写真实 scene | 已经并进 A（§8），而且是 B 能生效的前提 | **必做**，不能省 |
| 2. 面板「通过」时选场景 | 自动条目采集时已带真实 zone；手动条目仍没有 | **降级为可选精度项**：先靠通用分能进，想定向再加下拉 |
| 3. 自动候选 | 就是 B 本身 | 不重复做 |

补充一个 A+B 才会暴露的细节：给通用语料 +1 之后，如果某个 zone 在基础包里没有任何语料（比如 home_bed），通用语料会占满 3 个槽位，把基础包挤掉。需要加配额：**通用/进化语料最多占 1 个槽位（3 条里最多 1 条），除非场景匹配数为 0 才允许占更多**；同时同一句短期内不连续复用（记录 last_used）。
