# 一个饭点只吃一顿 + 小日记穿搭按块时刻（2026-11-20，7.6.1 / 守护 1.3.1）

起因是线上四张截图：她凭空说「好呀，那说定啦，今晚八点半左右去吃饭」；18:00 已和柳如烟约了火锅，却又买了一碗面；20:39 又冒出「和闺蜜吃饭」，日记里还写成沈幼微；19:09 的火锅日记写成「穿着白睡衣就下来了」；面板提示还是旧名「我想永远记住你」。

## 1. 解决了什么

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 没约她，却回「说定八点半吃饭」 | 守护 on_date_propose 用「foods ∩ 同意词」子串匹配，他说「我也去吃饭了」同时命中「吃饭」「去吃」 | 改 looks_like_date_invite()：要求指向词或祈使疑问句 |
| 2 | 火锅前又买面条 | 三餐只看钱包流水；社交消费「到点才扣」，18:00 账上干净 | 买前查日程占位（陪伴 meal_claim() / 守护 schedule_windows） |
| 3 | 面板旧名 | _conf_schema.json 两处硬编码旧名 | 改「我能永远记住你」+ 防漂移测试 |
| 4 | 日记把「闺蜜」写成沈幼微 | 提示词示例里就有「沈幼微」 | 改中性规则，泛称不许脑补具名 |
| 5 | 穿白睡衣去楼下小馆 | 日记按「现在」取穿搭（20:00 后是睡衣）；_at_home 不认 zone，楼下小馆被当在家 | 传块的 hour/place/zone；zone 优先；None 不算在家 |

附带修掉：_owner_umos 没挂到插件类（守护侧主动消息全哑）、天气 401 退避被 force 绕过、景区知识库误报、账单把晚餐记成午餐。

### 审查后追加的边界（2026-11-20 晚）

- 邀请判定排除过去时问句：「你吃饭了吗」「吃了没」不再建约会；
  补上无语气词的祈使：「去吃火锅」「吃火锅去」「好的，吃火锅」仍会建。
- 占位词表去掉单字「吃」：16:30 的「和同事吃点东西」不会占掉晚饭；
  `category=meal` 的块仍然直接算一顿（「在家随便弄点吃的」）。
- 守护侧占位命中**不再写死 meta**：饭局在窗口内取消后，这一顿还能补买。
- 架构棘轮修好相对 import 解析（原来只比较到包名，形同空转），
  并新增「date_engine → services.date_rules 这条边必须在基线里」的断言。

## 2. 行为变化（用户可见）

1. **一个饭点只吃一顿**：判定用宽窗口（早 6-10 / 午 10-15 / 晚 16-22），排时间仍用窄窗口（7:30-9 / 11-13 / 18-19:30）。15-16 与 22-24 是加餐/夜宵，不占位；奶茶/咖啡不占位。
2. **约会只在被明确邀请时创建**：必须带「一起/咱们/陪你/约你」这类指向词，或是「去吃火锅吧/吗/呢」这种祈使疑问句。他在说自己或别人吃饭，一律不算。
3. **一个饭点只约一场**：餐饮类社交邀约撞车直接婉拒（不再静默挪到 7 天内某天）；非餐饮保持原改期逻辑。
4. **小日记穿搭按块时刻**：19:09 的块永远写它那一刻穿的那套；事实池取「当天白天穿搭」，夜里不会被睡衣顶替。
5. **账单分类**：三餐按 slot 显式写分类，晚餐不再记成午餐。
