# 瘦身审查（2026-11-21，只报不改）

范围：能记（data）、能陪（forever）、能守护（watch）。

## 方法

1. AST 扫描所有 .py 的 import，统计每个生产模块的引用者，找出 0 引用模块；
2. 扫测试文件，找「有 test 但没有任何 assert」的可疑文件；
3. 人工复核候选（关键：子包模块会被误判）。

## 结论：不删

- 没有可靠的死代码。首轮列出的孤儿模块（forever 27 个、watch 一批）经复核全部是子包内模块：
  它们以 services.credit_engine、views.dashboard 形式被引用，扫描器按顶层名统计才显示 0 引用。
  删任何一个都会直接 ImportError。
- 测试没有可合并的重复文件。416 个测试文件里只有 1 个命中「无 assert」启发式，
  复核是断言写在辅助函数里，属误报。
- 生产代码 234 个 .py / watch 88 个，模块边界已经在 2026-11 的拆分里定过型，
  再做合并模块/抽公共库属于结构性改动，收益不明、回归面大，不做。
